# 康康健健 HealthDoc 本地运行与验收指南

> 文档状态：覆盖历史能力、第七轮资金闭环和第八轮智能搜索的本地运行方式。当前可运行基线仍为 SQLite schema v13，更新于 2026-08-07；第八轮无需迁移或重置数据。

智能搜索最小验收：启动前后端后访问公开目录，输入“女性”，应先出现安沐女性与家庭健康中心及匹配套餐建议；点击建议只在原页筛选。可分别请求 `GET /api/public/organizations?q=女性&search_mode=content` 和 `search_mode=hybrid` 检查 `search.mode`、`suggestions`、`matched_packages` 与 `match_reasons`。登录目录和预约页使用相同协议；预约页选择建议后仍需主动点击分院卡片。

当前本地门禁：

```powershell
Set-Location .\backend
.\.venv\Scripts\python.exe .\scripts\upgrade_local_database.py --check-only
.\.venv\Scripts\python.exe .\scripts\reset_v13_demo_data.py --check-only
.\.venv\Scripts\python.exe .\scripts\reset_v13_demo_data.py --apply --yes
.\.venv\Scripts\python.exe .\scripts\validate_v13_demo.py `
  --database .\instance\health_system.db --upload-dir .\uploads
.\.venv\Scripts\python.exe .\scripts\refresh_demo_media.py --check-only
```

重置会先备份 SQLite 与上传目录并严格拒绝未知账号；`test1` 随后应有 104 个活动指标、每项至少 9 条记录。旧重置入口仅作为历史兼容入口保留，新操作统一使用 `reset_v13_demo_data.py`。

付款验收从 `test1` 的“体检安排”提交订单开始；付款窗口不采集银行卡资料。机构账号从“收款与退款”查看净到账、期限和退款按钮；管理员从“平台财务”核对托管、服务费、退款义务和暂停分院。`validate_v13_demo.py` 是发布前唯一强校验入口。

本指南适用于完整健康服务平台：公开门户、三角色工作台、健康总览快捷测量、体检/自主记录时间线、同行体检安排、机构主体与分院协作、套餐版本与领域、亲友授权、报告识别导入和健康 AI。

### 版本演进与运行基线

- 1.0 建立了前后端分离、本地 SQLite、三角色登录和基础预约验收。
- 2.0 增加报告状态机、自主测量、时间线、趋势、亲友授权和 AI/OCR 开发模式。
- 3.0 将验收升级为 schema v8 的现实平台场景，包含分院协作、套餐版本、多人预约、候补通知和图文报告。
- 当前不再维护 1.0/2.0/3.0 的独立启动方式；历史能力已全部纳入 schema v13 的统一命令、账号和验收数据库。

## 1. 环境要求

- Windows 10/11、PowerShell 5.1+
- Python 3.10+
- Node.js 20+
- npm 10+
- 本地运行无需安装 MySQL、PostgreSQL 或其他数据库服务

## 2. 首次准备

在项目根目录执行：

```powershell
Set-Location .\backend

pip install -r requirements.txt

Set-Location ..\frontend
npm ci

Set-Location ..
if (-not (Test-Path .\backend\.env)) {
    Copy-Item .\backend\.env.example .\backend\.env
}
```

默认数据库：

```text
backend/instance/health_system.db
```

仓库跟踪一份可直接运行的 SQLite schema v12 预置业务快照，并同步跟踪 34 个清单化媒体文件，其中包括 19 份报告医学附件和 15 张分院封面。fresh clone 后数据库引用的媒体可直接使用。

## 3. 环境变量

离线验收建议保持：

```env
OCR_USE_MOCK=1
AI_USE_MOCK=1
```

真实 AI 需填写：

```env
AI_USE_MOCK=0
DEEPSEEK_API_KEY=你的密钥
```

真实华为云 OCR 需填写：

```env
OCR_USE_MOCK=0
HUAWEI_OCR_ENDPOINT=
HUAWEI_OCR_AK=
HUAWEI_OCR_SK=
HUAWEI_PROJECT_ID=
```

通知邮件默认使用 dry-run，不会连接外部邮箱：

```env
NOTIFICATION_EMAIL_DRY_RUN=1
```

需要真实投递时，配置 `SMTP_HOST/SMTP_PORT/SMTP_USERNAME/SMTP_PASSWORD/SMTP_FROM` 并把 dry-run 设为 `0`。注册必须填写有效邮箱，但邮箱只是通知渠道而不是账号唯一标识，多个家庭成员或验收账号可以共用同一个邮箱；空位提醒直接使用当前账号绑定的通知邮箱。邮件会以连续中文正文说明机构、日期、人数和下一步，不会发送 Outbox JSON 原文。本地验收可在被 Git 忽略的 `.env` 中设置 `DEMO_SHARED_EMAIL=你的测试邮箱` 统一绑定全部测试账号，也可用 `NOTIFICATION_EMAIL_REDIRECT` 临时把全部通知重定向到一个收件箱。真实邮箱不得写入受版本控制的文档或源码。

机构初始账密邮件还需要独立配置：

```env
ACCOUNT_CREDENTIAL_ENCRYPTION_KEY=至少32字符的高熵随机值
```

该值与 `AGENT_DATA_ENCRYPTION_KEY`、JWT 和 SMTP 凭据用途不同，禁止复用。真实密钥只能写入被 Git 忽略的 `backend/.env`，不得写入 `.env.example`、源码、截图、终端记录或文档；备份/恢复环境文件时必须保留该值，否则尚未发送且尚未清除的机构初始账密无法解密。已成功发送的 Outbox 会清除临时密文。

## 4. 数据库检查与升级

启动前检查：

```powershell
Set-Location .\backend
if (Test-Path .\instance\health_system.db) {
    .\.venv\Scripts\python.exe .\scripts\upgrade_local_database.py --check-only
} else {
    Write-Host "数据库尚未创建，首次启动会创建 schema v12。"
}
Set-Location ..
```

预期当前输出包括：

```text
user_version=13
expected_user_version=13
schema_current=yes
```

如果版本不是 12，停止后端后执行：

```powershell
Set-Location .\backend
.\.venv\Scripts\python.exe .\scripts\upgrade_local_database.py
Set-Location ..
```

脚本会先生成带时间戳的结构升级备份，在临时库完成结构、行数、完整性和外键验证后替换正式库。

```text
backend/instance/health_system.before-schema-*.db
```

不要在确认不再需要前删除该备份。

## 5. 开发模式

在项目根目录执行：

```powershell
.\scripts\start-full-dev.ps1
```

脚本会打开后端 PowerShell 窗口，并在当前窗口启动前端：

- 前端：<http://127.0.0.1:5173>
- 后端：<http://127.0.0.1:5050>
- 健康检查：<http://127.0.0.1:5050/api/health>

后端健康检查通过后，脚本还会启动隐藏的通知 worker。它每 5 秒处理预约、约满和空位提醒 Outbox；退出当前前端命令时 worker 会一并停止。若只启动后端和前端两个独立脚本，邮件 worker 也需要单独启动：

```powershell
.\scripts\start-notification-worker.ps1
```

Vite 会把 `/api` 和 `/uploads` 代理到后端 `5050`。

## 6. 本机生产验收

```powershell
.\scripts\start-full-prod.ps1
```

- 前端：<http://127.0.0.1:4173>
- 后端：<http://127.0.0.1:5050>

脚本默认只监听回环地址。首次运行若缺少 JWT 密钥，会在被 Git 忽略的 `backend/.env` 生成随机值，并设置仅当前进程有效的本机验收标志。

不得把本机验收配置直接暴露到局域网或公网。对外监听至少需要：

- `JWT_SECRET_KEY` 长度不少于 32；
- `DEFAULT_ADMIN_PASSWORD` 长度不少于 12；
- 防火墙访问限制；
- HTTPS；
- 完成生产数据库 schema v12 迁移与回滚演练。

## 9. 推荐完整验收顺序

### 9.1 公开门户与认证

1. 打开 `/` 和 `/explore/institutions`，未登录浏览启用机构、分院、在售套餐和“加入我们”固定联系方式。
2. 打开登录、注册页，确认图片验证码正常加载。
3. 注册页只允许普通用户；旧机构邀请链接明确返回“机构账号由平台管理员创建”。
4. 用不同角色登录，确认分别进入用户、机构和管理员工作台。
5. 尝试跨角色 URL，确认进入 403 或被后端拒绝。
6. 在同一浏览器打开两个标签页，分别登录不同账号并刷新页面，确认两个标签页仍各自保持原账号；在一个标签页退出，另一个标签页不受影响。

### 9.2 普通用户完整流程

用 `test1` 登录：

1. 用 `test6` 验证首次实名认证弹窗和 `IDENTITY_REQUIRED` 写门禁；用 `test1` 确认已确认的姓名、性别、出生日期不能自行修改。
2. 在“健康总览”查看健康摘要、领域卡片和最近动态，点击“记录测量”完成一次自主记录，不再进入独立测量板块。
3. 在“健康时间线”分别筛选“体检记录”和“自主记录”，确认本人录入的数据与机构归档结果都能看到；展开体检记录查看指标、文本结论和附件。
4. 在“健康趋势”按健康领域查看连续变化，确认同日存在机构结果时优先使用机构值，缺少机构指标时采用当天最后一次自主测量。
5. 在“体检预约”选择当前账号、关联账号和健康码临时参与人，验证最多五人、去重、明天至第 30 天、身高体重三种资料状态及脱敏回执。
6. 在预约卡确认预约、到检、报告上传、待复核、发布或取消节点；投诉入口按个人预约创建。
7. 浏览“体检机构”详情，确认机构介绍、服务能力、套餐版本、适用人群、包含领域、相册与评论都以服务产品方式呈现。
8. 在卡片式“亲友授权”接受关系并从头像菜单切换关联账号；健康页面不显示成员选择器，撤销关系后下游会话立即失效。
9. 在“我的评论”查看或删除本人评论；评论资格要求已有该机构发布的报告。
10. 打开健康 AI，先问普通问题，确认不加载报告；然后说“分析我上一次的体检报告”，确认自动引用并显示持续档案标签；继续问“这个报告里的 LDL 趋势”，确认无需再次选择，观察 SSE 状态、本次参考摘要和回答。

### 9.3 机构账号完整流程

用 `institution1_staff1` 登录：

1. 在机构运营总览切换分院/整个机构和 30/90 天、12 个月、全部，查看匿名画像、样本数和套餐建议。
2. 修改所属机构资料。
3. 维护套餐版本、适用人群和覆盖领域，提交新增、调整、下架或恢复申请；在“信息审核”查看处理进度或撤回。
4. 上传机构图片、拖拽排序并确认第一张成为普通用户封面。
5. 在“体检管理”从每日任务看板确认受检者到检，进入报告录入任务。
6. 录入标准指标、文本结论和附件，确认参考范围与异常提示；也可使用报告识别导入生成待复核内容。
7. 上传确认填写上传医生进入待复核；可修正后填写复核医生并发布。账号停用时拒绝，发布后内容不可编辑或撤回。
8. 确认预约同步变为已履约，普通用户的时间线、趋势和 AI 使用同一份归档结果。
9. 提交前确认页面明确提示不可撤回；归档后确认机构端不再显示撤下操作。
10. 在投诉处理回复待处理记录；用户升级后确认机构不可继续处理。执行注销预检并查看未结任务阻断项。

### 9.4 报告识别导入流程

在体检管理页把预约确认到检后选择“识别导入”：

1. 保持 `OCR_USE_MOCK=1` 完成离线验收。
2. 提交 PDF/PNG/JPEG/WebP；受检者、日期和套餐自动取预约快照。
3. 查看识别候选、置信度、冲突、未匹配和需复核项目；技术诊断中保留 `parser_version` 便于排错。
4. 对需复核项手工修正或补充，不把未知字段直接当成标准指标。
5. 确认草稿至少有一项指标，输入上传医生后进入 `pending_review`。
6. 待复核阶段修正结果，输入复核医生后发布；确认临时原文件删除，用户侧只能看到已发布内容。
7. 发布后验证报告进入对应用户时间线，预约状态变为已履约且报告不可修改。

### 9.5 系统管理员完整流程

用本机管理员账号登录：

1. 总览只显示账号、角色、机构、投诉和评论等非健康平台统计。
2. 新增分院时同步填写唯一机构用户名、初始密码和邮箱；检查凭据邮件状态/重试，再验证停用和恢复。
3. 在“审核记录”处理机构套餐新增、修改、下架和恢复申请；确认通过后生效、驳回后不变。
4. 查看并修正普通用户姓名、性别、出生日期，确认没有健康档案字段。
5. 查看账号，停用后确认该账号不能登录或刷新；再恢复。
6. 处理平台升级投诉并关闭；机构端不能越权继续回复。
7. 隐藏评论时填写原因并选择仅隐藏、7 天、30 天或永久禁言，处理待审/通过/驳回申诉。
8. 确认管理员页面没有报告、自测、时间线、趋势、健康档案或健康 AI。

## 10. 预约履约与自动归档验收建议

1. 普通用户预约机构、套餐和日期，确认状态为未履约。
2. 机构确认到检，任务进入报告录入阶段；身份、日期和套餐版本由预约带入。
3. 录入指标、锁定并提交，确认报告进入用户报告列表、时间线和趋势，预约变为已履约。
4. 另建预约后先确认用户与授权亲友时间线显示未履约；由机构标记已失效，确认同一预约事件更新为“该预约已失效，请重新预约或联系机构”，且无法上传报告。

## 11. AI 模式

Mock 模式不消耗外部额度，适合自动化与课堂验收。真实模式验收前：

1. 在 `backend/.env` 设置 `AI_USE_MOCK=0` 和 `DEEPSEEK_API_KEY`；
2. 重启后端；
3. 先测试公开 FAQ，再测试登录用户普通问答；
4. 最后选择已发布报告并确认同意；
5. 不在截图、录屏或日志中展示密钥、健康身份码和真实健康数据。

AI 结合当前问题、系统机构数据和所选健康档案生成回答，并保持同一对话中的档案上下文。

### 11.1 本地公共知识 RAG

RAG 只保存批准的公共知识，不保存用户问题、聊天、OCR 原文、用户/报告 ID 或健康指标值。首次在 `backend` 目录显式执行：

```powershell
.\.venv\Scripts\python.exe .\scripts\rag_sync.py sync
.\.venv\Scripts\python.exe .\scripts\evaluate_rag.py
```

## 15. 常见问题

### 后端提示 schema upgrade required

停止后端，先执行 `--check-only`，再运行升级脚本。确认备份文件生成后重新启动。

### 前端请求失败或代理到错误端口

确认后端监听 `127.0.0.1:5050`，访问 `/api/health`。使用完整启动脚本时不要手工改代理；自定义端口需同步 `VITE_API_PROXY_TARGET`。

### 登录或刷新返回账号不可用

账号可能被管理员停用。使用管理员工作台恢复后重新登录，旧 token 不应绕过状态检查。

### 机构邀请链接无法使用

这是 schema v12 的预期行为。机构账号不再自助注册，必须由平台管理员在新建分院时创建；历史邀请接口返回明确的停用提示。

### 报告无法上传确认或复核确认

确认预约绑定账号仍为启用普通用户、报告完整且医生姓名非空。身份、日期和套餐不允许在报告草稿修改；账号停用或状态并发变化时返回 409。

### 报告无法编辑

`draft` 和 `pending_review` 可按权限修正；`published` 内容不可撤下、删除或回到草稿。状态冲突统一返回 `REPORT_STATE_CONFLICT`。

### 普通用户看不到报告

确认报告是 `published`，`matched_user_id` 指向当前有效账号。用户只读接口不返回草稿或待复核报告。

### 趋势值与同日最后自测不同

同日存在已发布机构指标时，机构值优先；该指标未出现在报告中时使用当天最后自测。

### 报告识别返回错误或候选很少

确认文件格式、20 MiB 总大小、PDF 页数和 OCR 配置。未知或低置信度项目不会自动映射，需要人工复核或扩充指标字典。

### AI 提示未配置

离线验收设 `AI_USE_MOCK=1`。真实模式需填写 `DEEPSEEK_API_KEY` 并重启后端。

### Waitress 提示 JWT_SECRET_KEY

推荐从根目录运行生产验收脚本，它会为回环验收生成密钥。直接调用 Waitress 时必须手工配置至少 32 字符的密钥。

### 可以直接运行服务器发布脚本吗

可以使用根目录 `scripts/deploy-server.ps1`。只刷新 34 个清单素材时增加 `-SyncDemoMedia`，保留线上数据库；仅在隔离验收环境允许整体重建时才使用 `-SyncDemoDatabase`。两种路径都会先备份 openGauss、上传目录、环境文件与当前版本，失败时整体回滚；服务器既有 SMTP 配置保持不变。

## 17. Agent 本地验收

1. 执行 `python backend/scripts/upgrade_local_database.py` 升级到 schema v12。
2. 设置 `AGENT_ENABLED=1`；只读验收保持 `AGENT_WRITE_ENABLED=0`。
3. 前端默认读取 `/api/agent/capabilities` 自动切换；仅需强制回退旧 AI 时设置 `VITE_AGENT_ENABLED=false` 并重新构建。
4. 验证档案、趋势、机构和预约状态工具；再开启写开关验证草稿、拒绝、确认和重复确认。
5. 混合 RAG、OAuth、MCP 和 OTel 分别由独立开关启用，不允许一次性全开后跳过分层定位。
6. MCP 另运行 `python backend/mcp_server.py`，要求 OAuth、HTTPS issuer、resource URL 和至少 32 字符内部密钥。
7. 付费评测必须显式执行 `evaluate_agent.py --confirm-live --workers 1 --max-cost-usd 10`，脚本拒绝 Mock。本地 SQLite 使用单 worker；生产 openGauss 才允许提高并发。

详细变量、接口和安全门禁见《AI 与 OCR 开发说明》。
