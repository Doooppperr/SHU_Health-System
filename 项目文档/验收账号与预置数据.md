# 康康健健 HealthDoc schema v12 验收账号与预置数据

> 更新日期：2026-08-03。本文记录 schema v12 的账号、关联链、三类预约参与人、报告复核、投诉、评论治理、机构画像、指标和媒体验收方式。

第五轮全量趋势账号为 `test1`：104 个活动指标每项至少 9 条，核心趋势指标各 16 条；9 次综合体检和 20 次专项或联合复查覆盖 1458 天。全部报告严格继承套餐健康方向，含正常、偏高、偏低、少量阳性/阴性、OCR、手工录入、多机构、同日机构结果优先及标准附件批注。健康轨迹包括早期轻度超重、血脂/肝酶/尿酸波动，中期改善，一次阶段性反弹和近期 BMI 24.2 的轻度关注项。其他账号覆盖健康身份码亲友授权、代预约预约资料副本、机构取消及替代分院、无兄弟分院、性别参考规则、邮件重试和空数据页面。19 个报告附件按甲状腺/腹部超声、肺功能、十二导联心电图、胸片、心脏彩超和血细胞显微影像标准槽位关联报告记录。

## 1. 使用原则

- 验收以“现实人物完成一段健康服务旅程”为目标，不再为每个账号机械复制全部数据库状态。
- `backend/instance/health_system.db` 是可直接启动的 schema v12 预置业务快照；报告媒体的技术清单见 `backend/report_media_manifest.json`。
- 本文、预置 SQLite、15 张分院封面和 19 张报告附件均随 GitHub `main` 保留；不得只上传代码而遗漏预置业务快照。
- 正常启动不会覆盖本地操作。只有显式运行受保护的重置脚本，才会重建验收业务数据。
- 套餐表示健康领域服务，不承诺固定指标清单；机构实际完成的合法结果决定最终健康数据内容。
- 空位提醒不占位；健康码临时参与人只授予本次预约资格，不授予关联账号或健康数据查看权限。

### 1.1 验收场景的版本融合

- 1.0 的三角色账号、机构浏览、基础预约和管理员治理入口继续保留。
- 2.0 的自主测量、报告归档、时间线、趋势、亲友授权和 AI/OCR 旅程继续可验收。
- 3.0 在同一批账号上补充健康领域、套餐版本、多人预约、候补通知、图文报告、15 家分院和跨院只读场景。
- 账号不是按版本重复建立三套；登录同一账号即可看到从基础能力到当前平台能力的一条完整旅程。

## 4. 普通用户验收旅程

### `test1`：完整主旅程

1. 登录后在健康总览查看今日个人记录、下一次体检、最新机构健康数据和空位提醒。
2. 点击“记录今日测量”，新增、编辑、删除一条测量；个人历史继续出现在健康时间线和健康趋势，不进入“体检数据”。
3. 在健康时间线切换“全部、体检记录、个人记录”。个人测量按自然日合并；综合记录超过 15 条，可验证翻页。
4. 打开已完成的心电与循环检查，查看结构化指标、机构文字结论、报告附件和机构批注；用户端与机构端均在应用内弹窗查看，支持深色背景下缩放。
5. 查看包含本人、关联 `test2`、健康码临时 `test3` 的三人混合预约；确认三类来源去重且健康码临时添加不产生关联账号资格。
6. 在“体检预约”的预约记录区域确认显示“第 1 / 1 页 · 每页 10 组”；自动化测试使用 11 组响应验证第二页和相邻页不重复。
7. 在“体检机构”输入“澄心健康”“陆家嘴”“徐汇区”或地址片段，分别验证机构主体匹配保留全部分院、分院字段匹配只保留命中分院；清空输入恢复全部机构。
6. 查看已发送过提醒的空位订阅，确认系统明确提示“提醒不代表预约成功，也不会保留名额”。

## 5. 机构与管理员旅程

使用 `institution1_staff1`：

1. 在运营总览切换分院/整个机构和四个时间范围，查看匿名性别、年龄、套餐热度、样本数与套餐建议。
2. 从今日接待确认到检，再进入草稿和待复核任务。
3. 草稿上传确认时输入上传医生，进入 `pending_review`；修正后输入复核医生并发布，确认报告锁档、预约履约和通知同步完成。
4. 查看多人预约组，但只在鉴权后的详情中读取必要受检者信息。
5. 查看当前套餐、历史版本、待审核变更和管理员反馈。
6. 在“机构共享档案”只读查看同属澄心的浦东陆家嘴、闵行虹桥、黄浦人民广场和宝山顾村四家兄弟分院的 11 份已归档报告；点击“查看完整内容”可读取 15—25 项结构化指标、每个套餐方向的机构结论及有权限的附件，同时确认没有编辑入口且草稿不可见。
7. 在“体检套餐”设计新服务，确认适用人群范围仅提供“不限人群、男性、女性”三项，不再出现重复的“女性全龄”。
8. 在“投诉处理”回复 `institution_pending` 投诉并请求用户确认；用户升级后机构端不可继续处理。
9. 执行账号注销预检，确认未来预约、待上传/待复核报告和未解决投诉都会阻断。

使用 `institution2_staff1` 验证跨机构边界：不能读取澄心或云川的报告详情及附件；本院预约、容量和候补也不会出现兄弟分院数据。

使用 `demo_admin`：

1. 查看一条待审核、一条已通过和一条有明确理由的驳回套餐记录。
2. 新建分院时填写唯一用户名、初始密码和机构邮箱，检查凭据邮件状态/重试；不要在日志或文档记录真实初始密码。
3. 查看并修正普通用户姓名、性别、出生日期，确认响应和页面不包含健康档案。
4. 处理投诉升级；查看 7 天、30 天、永久处罚以及待审、通过、驳回申诉。
5. 确认管理员只能治理账号、身份基本信息、机构和公开内容，不能读取健康数据正文或检查附件。

## 6. 安全重置验收数据

停止后端后，在 `backend` 目录先预检：

```powershell
.\.venv\Scripts\python.exe .\scripts\reset_v12_demo_data.py --check-only
```

确认目标是本地当前 schema 预置库、账号清单完全匹配后，再显式执行：

```powershell
.\.venv\Scripts\python.exe .\scripts\reset_v12_demo_data.py --apply --yes
.\.venv\Scripts\python.exe .\scripts\validate_v12_demo.py `
  --database .\instance\health_system.db --upload-dir .\uploads
```

脚本会：

1. 备份 SQLite 和验收附件；
2. 保留管理员和每分院第一个机构账号；重复机构账号停用、解绑并递增安全版本；补齐 `test6`，形成 23 个启用可登录账号；
3. 在事务中替换机构资料、套餐、预约、健康数据、关联关系、参与人令牌、候补、通知、投诉、评论处罚/申诉和画像输入记录；
4. 生成不含真实隐私的验收检查图片；
5. 校验账号快照、外键、数据库完整性和附件 SHA-256；
6. 确认旧 A/B/C/D/E 套餐及 `BG-LEGACY` 预约组已经清除。

发现陌生账号、非 SQLite 数据库、非当前 schema 或不完整分院绑定时，脚本必须拒绝执行。应用正常启动绝不会自动清空已存在的业务记录。

重置脚本的固定业务目标继续包含 5 个机构主体、15 家分院、现有套餐、报告三态、分院封面和医学检查附件，并加入第六轮治理场景；`test1` 保持 104 个活动指标及长期趋势。每次验收的精确数量以只读 v12 校验器输出为准，不手工维护可能过期的统计。

## 7. 验收标准

- 登录 `test1` 即可看到完整、有上下文的用户故事，而不是平均分布的状态矩阵。
- 侧栏没有独立“日常测量”；旧地址会返回健康总览并打开测量面板。
- “体检数据”只包含 `published` 报告；时间线和趋势只读当前有效账号，预约卡展示预约、到检、上传、待复核、发布或取消节点。
- 兄弟分院只可查看已归档报告及附件并产生审计，草稿不可见、跨机构访问拒绝；预约与套餐等运营数据保持分院隔离。
- 机构详情不显示数据库枚举值或固定指标合同；新服务的适用人群范围只允许不限人群、男性和女性。
- 套餐、预约、候补、健康数据和机构任务均使用现实业务文案。
- AI 入口不遮挡列表、操作按钮或移动端内容。
- 后端测试、前端测试、生产构建、SQLite `integrity_check` 和外键检查全部通过。
- `validate_v12_demo.py` 必须只读；运行前后账号和业务行数一致，不能借应用启动自动补种来掩盖缺失 fixture。
