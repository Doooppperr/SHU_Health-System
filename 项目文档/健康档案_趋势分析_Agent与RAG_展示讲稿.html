01 · 展示定位

从“查看数据”到“让 Agent 完成目标”

核心故事：机构归档形成可信健康事实，多次记录形成趋势；Agent 根据用户目标选择受控工具读取证据、比较方案或生成任务草稿；公共健康知识则由混合 RAG 提供受控补充。

1. 看得清

时间线说明数据怎样产生，报告详情保留指标、结论和附件。

2. 看得懂

趋势计算由确定性代码完成，AI把结果解释成人能理解的语言。

3. 做得到

Agent 能搜索、比较、查询并生成操作草稿，但不能绕过用户确认。

02 · 健康事实入口

健康时间线：先证明数据从哪里来

现场操作

  1. 登录普通用户，点击左侧“健康时间线”，先停留在“全部记录”。
  2. 切换“个人记录”，指出机构和进度筛选会自动隐藏。
  3. 切换“体检记录”，找到“2026-07-24 糖脂代谢专项 · 已完成”。
  4. 依次指向“预约成功—机构确认到检—健康数据已归档”。
  5. 点击“查看本次健康数据”。
前一位同学已经展示了机构怎样录入、复核并正式归档检查数据。接下来我从普通用户角度继续展示：这些数据归档后，怎样形成长期健康档案，以及 Agent 为什么可以在不直接访问任意数据库的前提下完成分析和任务。

时间线不是简单的数据列表，而是按照真实日期，把预约、到检、归档和个人测量组织成连续历程。只有报告正式归档后，才会出现“查看本次健康数据”；尚未复核的草稿不会被当作最终健康事实。

同日个人测量

当天多次测量在时间线上合并展示，但原始时间和值仍保留在详情中。

体检业务状态

预约、到检和归档使用同一业务对象持续更新，用户知道结果如何产生。

本页总结句：Agent 处理的不是无法核对的聊天记忆，而是具有权限、状态和来源的正式健康事实。

03 · 正式报告

体检报告详情：结构化指标、机构结论与附件

现场操作 A：糖脂代谢专项

展示体重 71.9kg、空腹血糖 5.2mmol/L、总胆固醇 4.8mmol/L、甘油三酯 1.4mmol/L；随后展示机构结论、甲状腺超声、机构批注和图片放大。

一份正式档案同时包含三类内容：结构化指标及参考范围、机构复核后的文字结论、超声或影像等检查附件。普通用户只能查看，不能修改机构结果，因此历史事实不会被后续聊天或 Agent 回答反向改写。

现场操作 B：都市年度综合体检

  1. 打开“2026-07-26 都市年度综合体检”。
  2. 指出 104 项指标、8 个健康方向、8 条机构结论和 1 项需关注。
  3. 仅保留“基础体征与体格”，找到 BMI 24.2kg/m²。
  4. 指向参考范围 18.5—23.9 和“超重”结果标签，再恢复全部方向。
BMI 的结果状态来自报告数值、参考范围和机构结果，不是模型临时猜测。体重、身高等没有统一单项上下限的描述性数据不会被强行标记异常。这类计算和状态判断都由规则代码负责，模型只解释已经核验的证据。
答辩重点：“AI 能解释什么”取决于“系统能提供什么可信事实”；报告权限和正式归档状态始终在模型之前。

04 · 长期变化

健康趋势：先计算，再解释

现场操作

  1. 点击“健康趋势”，选择本人和“基础体征与体格”。
  2. 日期与来源先保持默认，点击“查看变化”。
  3. 点击“清空”，只选择“体重”和“体重指数”。
  4. 悬停数据点，展示日期、来源、参考范围和结果判断。
  5. 指向右侧与筛选条件联动的“AI 图表解读”。
单次报告回答“某一天是什么状态”，趋势回答“一段时间发生了什么变化”。当前数据中，体重从早期约 82kg 下降到近期 74.1kg，BMI 从 26.8 下降到 24.2；整体改善，但最新值仍略高于报告参考上限。

趋势起点、终点、变化方向和同日来源优先级都由服务端计算。AI图表解读只把这些已计算结果组织成自然语言，不负责重新计算，也不代替医疗诊断。
同一天出现多个来源确定性处理规则
既有机构体检结果，也有个人测量主趋势优先正式归档的机构结果
机构报告当天没有该指标采用当天最后一次个人测量
用户切换为“个人日常测量”仍可单独查看全部个人测量，原始记录不删除
本页总结句：图表每个点都能回到原始记录；Agent 调用趋势工具时得到的也是同一套确定性结果。

05 · 核心升级

从 AI 问答升级为可审计 Agent

旧 AI 问答

用户提问，模型读取准备好的上下文并生成回答，重点是“解释内容”。

HealthDoc Agent

用户描述目标，模型选择类型化工具完成查询、比较或草稿任务，重点是“完成目标”。

输入校验→紧急风险闸门→DeepSeek 规划→类型化工具→证据 / 草稿
用户确认→重新校验→领域服务提交→幂等回执
现在点击右上角“AI 健康助手”，打开后面板标题已经是“HealthDoc Agent”。它不再只有聊天气泡，还会展示任务轨迹、工具执行状态、证据、待确认操作和执行回执。

DeepSeek 负责理解目标和选择工具，但不能运行任意 SQL、访问任意网址或调用未注册接口。权限、数值计算、预约容量和写入都由后端领域服务负责。

当前类型化工具

档案列表报告事实指标趋势 机构搜索套餐比较名额查询 预约草稿取消草稿候补草稿客服工单草稿

紧急风险：胸痛、呼吸困难、疑似卒中、严重过敏、意识丧失、自伤风险等先由确定性规则短路，直接提示紧急求助，不等待模型规划。

06 · Agent 演示一

只读任务：报告分析与趋势解释

第一问：分析最近报告

请分析我最近一份体检报告里的异常项目，并说明依据。
这一轮 Agent 会先列出当前账号有权读取的已归档报告，再读取最新报告的结构化事实。面板中的“任务轨迹”会显示工具开始、完成和证据，而不是直接给出一段无法核对的回答。

如果回答提到 BMI 24.2 或其他项目，可以回到报告详情核对数值、单位、参考范围和机构状态。模型只能围绕工具返回的证据解释。

第二问：解释长期趋势

解释我最近几年的 BMI 趋势，列出起点、终点和总体变化。
Agent 会调用趋势工具。起点、终点、变化方向和样本日期由 Python/SQL 确定性计算，DeepSeek 负责说明“这段变化意味着什么、还需要注意什么”。这避免模型自己做长序列数值运算。
计划

先说明准备完成什么。

工具

展示实际调用与完成状态。

证据

回答可以回到原始业务数据核对。

演示观察点：任务轨迹出现 `list_reports`、`get_report_facts` 或 `compute_indicator_trend`；最终状态必须为完成，不能只展示自然语言回答。

07 · Agent 演示二

多工具任务：机构、套餐、名额和预约状态

第三问：套餐比较

比较云川影像与呼吸体检中心的“呼吸与肺功能专项”和“心电与循环影像专项”，重点说明价格和检查方向。
这不是让模型凭记忆推荐套餐。Agent 先搜索机构和当前有效套餐，再读取套餐价格、适用人群和健康方向，最后形成对比。套餐若已下架或版本变化，工具会返回当前业务状态。

第四问：查询未来名额

查询云川影像与呼吸体检中心未来 7 天的可预约日期。
名额不是由模型估算，而是预约领域服务根据日期、每日容量、现有有效预约和机构状态计算。DeepSeek只负责选择查询工具和组织结果。

可替换的只读问题

目标建议提问预期工具
搜索机构搜索提供呼吸系统检查的体检机构。search_institutions
套餐比较比较两项套餐的价格、方向和适用人群。compare_packages
查询名额查询指定机构未来 7 天名额。check_availability
预约状态查看我最近一笔预约的当前状态。get_appointment_status
本页总结句：Agent 的价值不是“回答得更像人”，而是把多个受控业务查询组合成一条可观察的任务链。

08 · Agent 演示三

写操作：只生成草稿，确认后才执行

最稳现场演示：客服工单草稿

请创建一个预约问题的人工客服工单，摘要写“现场 Agent 确认流程演示”，先生成草稿，不要直接执行。

现场操作

  1. 等待任务轨迹出现客服工单草稿工具。
  2. 指向“需要确认操作”卡片，说明参数和 10 分钟有效期。
  3. 强调此时数据库中只有加密草稿，还没有正式客服工单。
  4. 现场点击“拒绝”，展示状态回执；不要为答辩创建真实工单。
对预约、取消、候补和人工客服工单，Agent 永远不能直接提交。它只能生成一张待确认卡片。用户点击确认后，服务端还会重新检查账号、授权、套餐版本、名额、预约状态和草稿有效期，再调用与原业务页面相同的领域服务。

如果网络重试或用户重复点击，同一个 Action ID 作为幂等键，只返回原回执，不会生成第二个预约或第二张工单。
草稿，无副作用→用户查看摘要→确认或拒绝→重新校验→一次性提交 / 回执

可以由 Agent 决定

选择哪个已注册工具、以什么顺序查询、怎样解释工具证据。

必须由用户决定

是否预约、取消、进入候补或创建人工客服工单。

09 · 模型与知识

为什么使用专项小模型，而不是再部署一个通用小 LLM

组件负责什么为什么这样分工
Python / SQL 领域服务权限、趋势计算、容量、状态转换、幂等写入结果可复现、可测试，不把精确计算交给概率模型
DeepSeek V4 Flash目标理解、类型化工具选择、多步规划、证据解释具备较强工具调用能力，服务器无需常驻大语言模型
BGE-small-zh公共知识 Dense 语义召回中文语义匹配能力好，资源占用远小于通用 LLM
BM25 + 中文词法Sparse 关键词和专业术语召回对指标名、疾病名和精确词语更稳定
RRF融合 Dense 与 Sparse 候选减少只依赖单一路径造成的漏召回
当前生产机只有约 4GB 内存，因此没有常驻 0.6B 到 7B 的通用小语言模型。小模型被用在它真正擅长的检索环节，DeepSeek负责规划，确定性代码负责业务正确性。这比让多个语言模型重复分析同一份数据更稳定，也更容易审计。

Agent 与 RAG 的边界

Agent

处理私人档案、趋势、机构目录、套餐、名额和任务草稿；只调用类型化业务工具。

混合 RAG

为健康 AI 分析模块提供提前审核的公共健康知识；不保存私人档案，也不是实时上网搜索。

线上混合索引已启用：7 个批准来源、665 个知识块；Dense 与 Sparse 各预取 24 个候选，RRF 合并 12 个，再按指标和来源进行确定性重排。

11 · 现场保障与答辩

失败备用方案与老师可能追问

现场超过 15 秒未返回

HealthDoc Agent 使用流式事件展示计划、工具和证据。现在智能服务没有及时响应，为避免占用展示时间，我使用提前准备的成功画面说明。重点不是一句生成文本，而是任务轨迹、工具证据和写操作确认边界。

必须准备的备份画面

  1. 最近报告分析：包含任务轨迹与工具完成状态。
  2. BMI 趋势：包含趋势工具和起止值。
  3. 套餐比较或名额查询：包含多工具证据。
  4. 客服草稿：包含确认卡片与拒绝回执。

6 分钟压缩路线

  1. 30 秒说明健康事实来源。
  2. 1 分钟展示报告和趋势。
  3. 2 分钟演示报告分析与套餐比较。
  4. 1 分钟演示写操作确认并拒绝。
  5. 1 分钟说明小模型与安全边界。

高频追问

问题回答要点
Agent 和普通 AI 问答有什么区别？问答生成解释；Agent 选择受控工具完成多步目标，并展示轨迹、证据、确认和回执。
为什么不部署一个本地小 LLM？4GB 服务器不适合常驻通用模型；专项检索小模型更省资源，业务正确性由确定性代码保证。
模型会不会直接修改预约？不会。模型只生成草稿；第一方界面确认后，服务端重新校验并幂等提交。
RAG 会保存用户报告吗？不会。公共 RAG 只存批准的公共知识，私人档案按请求权限读取。
Agent 是不是医疗诊断？不是。它解释正式报告、趋势和公共知识，正式结论仍来自机构或医生。

12 · 最终检查

现场措辞检查表与固定提问

不要这样说应该这样说
Agent 可以直接访问数据库。Agent 只能调用注册过的类型化工具，工具内部执行权限和字段约束。
DeepSeek 计算了 BMI 趋势。趋势由后端确定性计算，DeepSeek 负责选择工具和解释结果。
Agent 会自动完成预约。Agent 只生成草稿，用户确认后才由预约领域服务提交。
RAG 就是实时上网搜索。RAG 检索提前审核并同步的公共健康知识。
小模型负责判断用户该买什么套餐。小模型负责知识召回；套餐事实来自业务工具，选择权仍属于用户。
刚才回答一定用了 RAG。只有检索状态和来源证据显示命中时，才能说明使用了公共知识。
MCP 已经对公网开放。MCP 已实现，但当前等待可信 HTTPS，生产保持关闭。

  3. 比较云川影像与呼吸体检中心的两项专项套餐，说明价格和检查方向。

最终记忆句：
单次报告是一张健康快照，趋势是一段长期变化；HealthDoc Agent 负责选择受控工具完成目标，混合 RAG 负责补充审核后的公共知识，所有写操作都必须经过用户确认。
