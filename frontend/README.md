# 康康健健 HealthDoc 前端

Vue 3 + Vite 6 前端采用“公开机构目录 + 三角色工作台”的页面结构。当前基线为 schema v13，覆盖在线付款、资金进度、投诉与退款、机构收款与退款、平台财务，以及原有预约、报告、健康档案和 HealthDoc Agent。第八轮统一了三处智能搜索体验与访客顶部导航；当前运营修复增加机构身份锁定提示和统一备案入口。

## 第八轮搜索与访客导航

- `SmartInstitutionSearch.vue` 由公开目录、登录目录和预约页共同复用：防抖后先请求内容搜索，后端提示需要意图理解时再请求混合搜索；请求版本号阻止旧响应覆盖新查询。
- 建议按机构、分院、套餐展示，支持关键词高亮、加载/降级/空状态、方向键、Enter、Esc、鼠标和触屏。点击建议只在当前页面过滤结果，不显示模型分析、匹配字段或推荐原因；预约页仍要求用户主动选择分院。
- `PublicHeader.vue` 由首页和公开目录共同复用。桌面采用对称三列以保证导航几何居中，中等宽度收起次要锚点，小屏改为独立导航行；登录、注册、工作台、主题和关怀模式行为保持不变。
- 机构资料页把机构主体、分院名称、区域和地址显示为锁定身份信息；只提交电话、交通、分机、轮休日和简介。`IcpFilingLink.vue` 在公开首页、公开目录和工作台侧栏复用，统一链接工信部备案系统。

## 1.0—3.0 前端演进

- 1.0 建立公开入口和普通用户、机构、管理员三套基础页面。
- 2.0 将健康记录提升为总览、时间线和趋势，并把机构报告整理成任务状态流。
- 3.0 采用卡片、步骤向导和任务工作台重构数据库式页面；日常测量收拢到总览，AI 移入顶栏，机构按主体/分院展示并增加跨院只读档案。
- 当前路由只呈现融合后的 3.0 体验；兼容路由负责把旧书签引导到新页面，不维护旧 UI 副本。

## 页面与路由

### 公开页面

| 路由 | 页面 |
|---|---|
| `/` | 项目介绍、核心能力、流程、隐私提示和关于我们 |
| `/login` | 带图片验证码的独立登录页 |
| `/register` | 仅普通用户注册；机构账号由系统管理员随分院创建 |
| `/explore/institutions` | 访客浏览启用机构、分院和在售套餐 |
| `/explore/institutions/:id` | 访客查看公开机构与套餐详情；预约动作引导登录并保留参数 |
| `/403` | 无权访问 |
| 未知路径 | 404 页面 |

登录用户访问登录/注册页会按真实角色返回所属工作台。

### 普通用户工作台

入口为 `/dashboard`：

| 路由 | 功能 |
|---|---|
| `/dashboard` | 健康总览、最近动态与“记录测量”快捷入口 |
| `/timeline` | 体检记录与自主记录统一时间线，支持按记录类型筛选 |
| `/measurements` | 兼容旧地址，自动返回健康总览并打开测量入口 |
| `/trends` | 查看当前有效账号的连续变化与独立异常提示 |
| `/health-data`、`/health-data/:id` | 当前有效账号的已发布体检数据与详情 |
| `/reports`、`/reports/:id` | 兼容既有深链接，报告内容统一回到健康时间线查看 |
| `/friends` | 卡片式关联账号申请、接受、双方备注、切换和撤销 |
| `/institutions`、`/institutions/:id` | 机构、封面、套餐与评论 |
| `/appointments` | 三类参与人的多人预约、受检预约、代预约回执和投诉入口 |
| `/comments/mine` | 我的评论 |
| `/profile` | 账号、健康身份和个人健康资料 |
| `/agent-actions/:id` | 第一方 Agent 写操作确认与结果回执 |
| `/oauth-consent` | 外部 Agent 的 OAuth scope 授权确认 |

普通用户可为当前有效账号、已关联亲友或健康身份码临时参与人创建最多五人的体检安排。健康码临时添加只授予本次预约资格；健康时间线、体检数据和趋势始终读取当前有效账号，查看其他关联账号前必须先从头像菜单切换。

### 机构账号工作台

入口为 `/org/dashboard`：

- 分院/整个机构、30 天/90 天/12 个月/全部范围的匿名经营画像与套餐建议；
- 每日预约看板、名额设置与按套餐领域的健康数据生产；
- 机构资料维护；
- 机构相册管理；
- 套餐变更申请和信息审核记录。
- 投诉处理与机构账号注销预检。

`/org/reports` 已命名为“体检管理”。机构按“预约到检—报告录入—结果复核—归档发布”的实际工作流程处理任务，可手工录入或使用报告识别导入；受检者、日期和套餐来自预约，只需复核检查结果。发布后报告永久归档、预约变已履约，不提供撤下操作；历史未绑定预约报告继续只读展示。

### 系统管理员工作台

入口为 `/admin/dashboard`：

- 系统运营总览，仅显示账号、机构、投诉、评论等非健康统计；
- 机构与相册管理、套餐只读查看；
- 机构套餐新增、修改和上下架审核记录；
- 新建分院时同步设置唯一机构用户名、初始密码和机构邮箱；
- 账号停用、恢复和删除；
- 普通用户基本身份查看/修正（不含健康档案）；
- 投诉接管、回复和关闭；
- 评论隐藏、7/30 天或永久禁言及申诉处理。
- Agent 人工工单接手/解决/关闭与 OAuth 客户端批准/拒绝/撤销。

系统管理员没有报告、指标、自测、时间线或个人健康资料入口。

## 公共交互与基础能力

- 公开门户、独立登录/注册和图片验证码；
- 三角色路由、菜单和工作台隔离；
- 未登录机构列表、详情、套餐、相册封面、“加入我们”联系方式和加载失败占位；
- 关联账号卡片与受控切换；撤销后下游切换会话立即失效；
- 用户评论、禁言提示、单次申诉和管理员治理；
- Agent 计划/工具/证据 SSE、确认卡、取消/重试和旧 AI 回退；
- 关怀模式、AI 顶栏入口、桌面侧栏自适应重排和窄屏 overlay。

“加入我们”的运行时联系方式统一读取 `GET /api/public/contact`；页面内默认占位只用于接口失败降级，正式口径以服务端 `platform_contact.py` 为准。

## 角色路由保护

路由元数据限定 `user`、`institution_admin`、`admin`：

- `user → /dashboard`
- `institution_admin → /org/dashboard`
- `admin → /admin/dashboard`

未登录访问工作台会跳转 `/login`；跨角色进入 `/403`。登录、刷新令牌或重新获取当前用户后，前端使用后端返回的实时角色重建导航。后端仍执行独立鉴权，前端守卫不承担唯一安全责任。

访问令牌、刷新令牌和当前用户保存在当前标签页的 `sessionStorage`。同一浏览器可以在不同标签页分别登录不同账号，后登录的标签页不会覆盖已打开标签页的会话；退出登录也只清理当前标签页。旧版共享 `localStorage` 登录数据会在首次加载时迁移一次并删除共享副本。

## 机构相册与用户机构页

机构账号和系统管理员页面继续支持 JPEG、PNG、WebP 上传、每张 5 MB、每机构 8 张、拖拽排序和删除。第一张是封面。普通用户列表和详情优先读取 `cover_image_url`，兼容 `logo_url` 与 `images[0].image_url`；无图片或加载失败时显示可访问占位，不影响资料、套餐和评论。

## 健康时间线、趋势和报告

- 时间线、体检数据和趋势不再带成员选择器，统一读取 JWT 中的当前有效账号；关联账号切换由独立受控会话完成。
- 趋势页面按健康方向和指标请求每日有效序列，并单列最近异常、全部异常及“历史异常，最新已恢复正常”。
- 同日机构发布指标优先于自测；缺少机构指标时可回退到当天最后自测。
- 报告列表和详情完全只读，不显示健康身份码、创建机构账号、临时原文件或内部匹配用户 ID。
- 健康码预约匹配仅显示姓名、性别、出生年份和脱敏身份码；不展示联系方式、病史或历史身高体重数值。

## AI 智能助手

- 公开门户、登录和注册页显示访客 AI，仅回答公开导览。
- 普通用户工作台显示健康 AI；打开侧栏时不立即请求报告列表。
- 用户主动“引用报告”或收到 `select_records` 动作时才按需加载可分析报告。
- 报告选择支持精确选择与“该归属人的全部已发布报告”两种范围；检索阶段显示独立状态。
- 选择内容后需明确同意发送指标；选择和同意只对当前请求生效，完成、取消或改变选择后重置。
- 用户消息先显示，AI 使用 SSE 逐步拼接；发送中防重复，支持 AbortController 取消、失败保留和按 `retryable` 重试。
- 会话只保留在当前标签页 `sessionStorage`，退出或结束会话清理；悬浮球位置与侧栏宽度可存 `localStorage`，不包含健康数据。
- 机构账号和系统管理员工作台不显示健康 AI。
- 桌面端 AI 从顶栏打开，主内容按剩余空间自然重排；空间不足或移动端切换为有焦点管理的遮罩对话框，不整体缩放页面。

## HealthDoc Agent

- 应用启动读取 `/api/agent/capabilities`；服务端启用时自动使用 `AgentAssistant`，禁用或不可用时保留原 `AiAssistant`。
- 浏览器只保存当前 thread ID；会话正文、活动轨迹和待确认 Action 从服务端恢复。
- `meta/plan/tool_started/tool_completed/evidence/approval_required/delta/done/error` 事件驱动内部状态与审计；普通用户只看到业务化处理状态、回答、确认卡和回执，不展示原始工具名或任务轨迹。
- 预约、取消、候补和人工工单以确认卡呈现；批准或拒绝都调用独立 SSE 决策接口，重复批准显示同一幂等回执。
- 管理员 `/admin/agent-ops` 只看人工工单摘要和 OAuth 客户端元数据，不显示健康档案或 Agent 会话正文。
- `VITE_AGENT_ENABLED=false` 是构建级紧急回退；默认由后端 capability 决定。

## 关怀模式与响应式布局

关怀模式放大文字和关键控件，并通过断点、换行和弹性布局适配不同宽度。AI 侧栏打开后页面按可用空间重新排布；安全宽度不足时使用遮罩层，避免导航重叠和横向滚动。

## API 模块

`src/api/http.js` 统一注入 JWT，并处理刷新流程。当前主要模块：

- `auth.js`、`users.js`：认证与账号；
- `profile.js`：本人个人资料；
- `health.js`：自测、时间线和趋势；
- `examReports.js`：用户只读报告；
- `org.js`：机构运营与报告生产；
- `public.js`：访客机构、分院和套餐只读目录；
- `appointments.js`：参与人令牌、多人预约、受检预约、代预约回执和预约事件；
- `complaints.js`：用户、机构和管理员投诉状态流；
- `admin.js`、`dashboards.js`：系统管理；
- `institutions.js`、`friends.js`、`comments.js`、`indicators.js`：延续功能；
- `ai.js`：报告选择和旧 SSE AI；
- `agent.js`：Agent thread、运行/决定 SSE 和工单运营；
- `oauth.js`：第一方授权和管理员客户端审批。
